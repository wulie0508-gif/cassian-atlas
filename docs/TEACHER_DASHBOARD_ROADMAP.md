# Cassian Atlas 教师看板迭代路线

## 产品定位

Cassian Atlas 的网页是本地、只读的教师决策台，不是第二套录入系统。学习事实、批改、选题、课件生成和运行状态继续由 Codex / CLI 通过审计接口完成；网页只负责把已经确认的数据组织成可快速判断的状态。

首页必须优先回答四个问题：

1. 最近一组可比较的训练是否进步；
2. 下一节课最值得处理什么；
3. 到期复测是否积压、旧错是否恢复；
4. 日常训练是否已经有线下闭卷证据校准。

## 不变边界

- 网页不创建、修改或删除学习事实；
- 网页不直接写 SQLite，不提供成绩录入、批改、选题或课件生成表单；
- 不把不同题型、不同训练系列或不同满分的成绩连成一条趋势；
- 暂定薄弱信号与稳定薄弱点分开显示；
- 没有线下闭卷证据时明确显示“尚无校准”，不预测考试分数；
- 学生、学科、原始答案和运行记录必须隔离；
- 题库、原始资料、本机路径和学生隐私不进入公开仓库。

## 第 1 轮：教师决策首页

目标：把首页从系统介绍页改成教师能在一分钟内读完的教学驾驶舱。

- 新增统一的教师聚合接口，后端一次性固定计算口径；
- 首屏展示近期可比正确率、到期复测、稳定薄弱点和线下校准；
- 展示唯一的下一节课建议及依据；
- 展示最多六次同口径表现、五个稳定薄弱点和五次近期课程；
- 区分最后学习记录、最后有作答活动和最后可评分作答；
- 显示答案采集、知识映射、错因诊断和用时覆盖，不把数据缺口藏起来；
- 修复健康检查、请求串屏、空学生、加载失败、移动端导航和无障碍基础问题。

验收门槛：完整测试通过；健康接口稳定低于服务管理器超时；320、390、768、1024、1440 像素下无页面级溢出或关键控件裁切；网页继续满足只读契约。

## 第 2 轮：错题与复测工作台

目标：回答“哪些错误已经解决，哪些仍在重复”。

- 增加只读的复测队列页，按领域、到期时间和重复错误次数筛选；
- 将知识点、原题证据、最近复测和错因状态放在同一条记录中；
- 单独列出样本不足、等待原始答案和等待人工确认的信号；
- 为教师提供可复制给 Codex 的最小复测需求，不在网页执行选题；
- 支持从薄弱点跳转到相关课程记录和已核验题目。

## 第 3 轮：同口径趋势与过关判断

目标：回答“能否进入下一板块”。

- 只按同一 `assessment_kind + reporting_series + score scale` 显示趋势；
- 支持最近一周、上一周和滚动四周对比，并始终显示样本量；
- 分开显示首次作答、重复练习和复测恢复；
- 支持教师设定的过关标准，但标准通过 CLI 配置，网页只读展示；
- 将日常训练与线下闭卷校准并排呈现，不互相覆盖。

## 第 4 轮：课程证据链与家长周报预览

目标：让教学投入、课堂内容和结果变化可追溯。

- 课程记录按时间线连接材料、作答、薄弱点变化和复测；
- 周报预览只使用已有证据，明确数据范围和缺口；
- 导出仍由 Codex / CLI 生成，网页只展示最近生成状态和来源快照；
- 不增加收费、排课或家长账号系统。

## 第 5 轮：多学生教师工作区

目标：在不牺牲隔离和隐私的前提下支持真实多学生使用。

- 学生切换使用显式学生标识并防止旧请求串屏；
- 学科页面只读取该学生已注册学科的数据；
- 增加多学生概览时只显示最小教学状态，不暴露教师备注或原始答案；
- 在考虑局域网访问之前先完成认证、字段脱敏和权限模型。

## 每轮固定流程

1. 从真实数据库和当前页面做只读基线审计；
2. 将口径写入后端或契约测试，避免前端临时重算；
3. 使用小范围文件改动实现一个可验证增量；
4. 运行单元测试、隐私检查和真实数据库质量检查；
5. 用浏览器检查桌面、平板、手机、键盘和错误状态；
6. 重启本地服务并把结果写入 Agent 运行台账；
7. 只有当前轮达到验收门槛后才进入下一轮。

大量模型预算用于增加证据、测试和产品质量，不以消耗 token 本身作为目标。
