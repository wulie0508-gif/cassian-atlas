# Public showcase boundary

The public OpenTutor Ledger showcase is a static, synthetic product tour. It is intentionally separate from the private Teacher Console.

## Architecture

```text
GitHub Pages                         Teacher workstation
site/                               127.0.0.1:8788
├─ static product narrative         ├─ private SQLite evidence ledger
├─ manually authored demo values    ├─ licensed or private content adapters
└─ no API or runtime connection      └─ audited Codex and CLI writes
```

The showcase has no database, authentication state, learner identifier, API client, analytics tracker, or hidden connection to a local runtime. Its Content Security Policy sets `connect-src 'none'`.

## Synthetic-data contract

Every person, score, attempt count, event, priority, and timeline shown in `site/` is manually authored for demonstration. The data is not exported, anonymized, sampled, or transformed from a real learner. The machine-readable [demo manifest](../site/demo-manifest.json) declares this boundary.

Allowed public examples:

- an identity explicitly labelled as `Demo learner` or `示例学生`;
- generic knowledge labels and manually authored metrics;
- synthetic workflow events and architecture diagrams;
- original, short interface copy.

Never publish:

- names, answers, scores, notes, or timelines belonging to a real learner;
- question-bank, textbook, exam, OCR, audio, or answer-key content;
- database names, local paths, run payloads, or private configuration;
- a demo generated by anonymizing or perturbing real learning data.

## Release gate

The Pages workflow runs the complete unit suite, privacy audit, public-site contract tests, and JavaScript syntax checks before deployment. Only the `site/` directory becomes the Pages artifact. The Python application, local configuration, and private runtime are never deployed as a public service.
